# Phase 4 새 검증 확대·전체 생성 정책

이번 작업은 1) 새로운 train 수치 검증, 2) 별도 버전 데이터 생성·무결성 확인이다.
GUI, v2 원자료, v3 파일럿 및 기존 분석 산출물은 보존한다. ML·포스터 분석은 하지 않는다.

## 검증 사례 선정 (결과를 보기 전에 고정)

기존 대표 19개를 제외한 train에서 96개 시나리오를 선정한다.
scenario_type × obstacle_layout의 각 셀에서 seed=20260912로 하나씩 뽑고,
train의 작은 양의 장애물 여유(0~0.05), 특이점 지수<0.05, 시작/도착 바깥 경계 2% 이내,
도달불가 후보 포함 각각 최대 8개를 추가한다. 중복은 제거하고 남은 수는 동일 RNG로 채운다.
항상 선택된 시나리오의 42개 후보를 모두 다룬다. 기존의 19개 사례는 별도 회귀군이다.
결과에 유리하게 사례/허용오차를 바꾸지 않는다. 선택 ID와 소스 해시를 먼저 저장한다.

## 계산·채택 정책

- 버전 phase4-mathematics-v3 / release-generator-v1. v3-pilot과 구분한다.
- Eθ/A/J: 기존 v3의 독립 미분 + QUADPACK 구간/GL32 가중합 유지.
  경고·오류·비유한값·시간표본 미분 실패는 unresolved로 처리한다.
- L/Kε/O: 평가식과 원 161점 값을 유지하되, **각 유효 후보마다** 321/641점 검산을 추가한다.
  161 대 641 및 321 대 641이 모두 기존 허용값
  L(atol=1e-6, rtol=.005), Kε(1e-6,.02), O(1e-4,.05)를 통과해야 한다.
  epsilon은 고정. 실패 지표와 세 해상도 값을 저장하며 그 후보는 unresolved다.
  641점은 고해상도 비교 기준이지 참값이 아니다. 원 L/K/O 숫자는 진단용으로 보존한다.
- 검증 확대 96개에서는 통과한 관절 적분을 2561점 독립 미분 사다리꼴과 비교한다.
  E(1e-6,.01), A(1e-5,.02), J(1e-3,.05). 비교 불일치 실행은 이후 생성에서 보류한다.
- 도달/충돌 구간 검사는 이전 고정 설정 유지. invalid, unresolved, accepted를 구별한다.
  안전성/정확도에 관한 엄밀한 보증이 아니며 미확정을 경로 부재로 해석하지 않는다.
- 미확정 대안이 있는 시나리오의 승자는 **잠정**이다. 새 가중치/곡선 수를 도입하지 않는다.
  전체 파일의 완료 상태와 학습 정답 사용 가능 여부는 별개다.

## 전체 생성 및 분할 보호

원 scenarios.csv의 입력과 scenario_id/split을 그대로 사용해 5,500개 시나리오를 재계산한다.
train 3,000 / validation 1,000 / test 1,000 / challenge 500. 후보 42개씩.
학습이나 가중치 조정은 하지 않는다. train 96개 검증 완료 후 생성 설정을 동결한다.
held-out에서는 계산·저장 및 기계적 키/행 수/스키마/해시 검사만 한다.
held-out 점수 분포·순위/승자 비율·유효율을 집계하거나 표시하지 않는다.

시나리오별 압축 JSONL+Parquet와 완료 마커/해시. 전체 시간을 메모리에 올리지 않는다.
재개는 소스·정책·입력 해시가 같을 때만 가능하며 완료 파일의 해시를 확인한다.
미완료 시나리오는 기존 부분파일을 지우지 않고 새 attempt 폴더에서 다시 생성한다.
기존 출력 폴더 덮어쓰기 금지. 원자료/파일럿과 버전·폴더·키를 명확히 구분한다.
